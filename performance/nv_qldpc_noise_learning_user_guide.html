Learning Noise From Detector Data and Decoding With the Learned Rates

A detector error model (DEM) tells a decoder which error mechanisms can occur, but a decoder also needs to know how likely each one is. On a real device these rates are not known in advance and they drift. The NV-qLDPC decoder package can learn them: given only the detector outcomes recorded from the device (no logical labels, no knowledge of the noise), it estimates the rate of every error mechanism on the GPU. The learned rates are then used as the decoder’s prior.

This page measures the whole workflow on a circuit-level noise model with 67,752 error mechanisms. We start from a single uniform guess, learn the rates from simulated device data, and compare the logical error rate (LER) of the decoder under three priors:

  • uniform – one rate for every mechanism, the starting point of learning (no knowledge of the noise);

  • learned – the rates returned by learn_noise;

  • oracle – the true rates of the circuit that generated the data (the best a prior can do).

The main results, measured on one GB200 with the bivariate-bicycle [[144,12,12]] code, 12 rounds and si1000 noise, are:

  • Learning from 2,097,152 shots takes about 15 minutes with the default settings and about one hour with passes=16, tol=0.

  • With passes=16, tol=0 the observed LER with the learned prior is 1.00x to 1.05x that of the oracle prior at p = 0.002, 0.003 and 0.004. The confidence intervals overlap; these runs do not establish equivalence within 5%.

  • Compared with the uniform prior, the learned prior lowers the LER by 22x, 30x and 9.8x at the three physical error rates.

  • The error of the learned rates keeps falling by about 1.4x for every doubling of the number of shots, down to 1.8x to 3.1x above the sampling floor at 2.1M shots.

The study uses the TCBP decoder with JOBS post-processing (osd_method=4, osd_init_method="tcbp"). See Noise Learning and Trajectory-Calibrated BP for what these are and for the full set of options, and Trajectory-Calibrated BP and Jittered OSD Beam Search for a performance study of the decoder itself.

Experiment Setup

Decoder and experiment parameters

Parameter

Value

GPU

NVIDIA GB200 (one GPU per physical error rate)

Code

bivariate-bicycle [[144,12,12]], A = x^3 + y + y^2, B = y^3 + x + x^2

Rounds r

12, Z-basis memory experiment

Noise model

si1000 circuit-level noise, p = 0.002, 0.003, 0.004

Circuits

TCBP model

Learning data

simulated detector shots from the circuit itself (stim detector sampler, seed=10001); smaller shot counts are prefixes of the same sample

Learning

learn_noise, mode="per_mechanism", either default settings (passes=4, tol=0.1; every default run on this page ran the full 4 passes) or passes=16, tol=0

Uniform prior

a single rate for all mechanisms: the start_rate that learn_noise derives from the mean detector event rate of the data (4.86e-4, 6.88e-4, 8.67e-4 for p = 0.002, 0.003, 0.004)

Learned prior

rates learned with passes=16, tol=0 from 2,097,152 shots

Oracle prior

the true DEM rates of the circuit

BP

sum-product (bp_method=0), max_iterations=10, clip_value=15.0, proc_float="fp32", use_sparsity=True

Post-processing

JOBS: use_osd=True, osd_method=4, osd_init_method="tcbp" (OSD column ordering from the TCBP model)

jobs_search_converged

False (default): the JOBS search is skipped on shots where BP converges. True runs it on every shot, which is slower but more accurate, mostly at low p. All runs on this page use False.

Decoding data

fresh simulated shots (stim detector sampler, seed=778), same stream for all three priors, decoded in batches of 4,096 (bp_batch_size=4096); error_rate_vec clipped to [1e-9, 0.45]

Stopping rule per arm

200 logical failures, or 2,000,000 shots, or 3,300 s of wall time, checked after every batch (an arm can overshoot 200 failures by up to one batch)

Logical failure

any of the 12 observables predicted wrongly, or a decoder output that does not reproduce the syndrome (none occurred)

Software

CUDA-Q QEC 0.9.0 pre-release, commit d5a63081 (nv-qldpc-decoder built for sm_100); stim 1.16.0, scipy 1.18.1, numpy 2.5.4

The “device” is simulated: detector samples are drawn from the si1000 circuit with stim, and the true rates of that circuit are kept aside to score the result. The learning step never sees them. With real hardware, pass the recorded detector data instead.

The three steps below are one script and run as written, in order. The script needs a GPU, cudaq_qec with the nv-qldpc-decoder plugin, and stim. To keep the run short it uses the p = 0.004 circuit, 65,536 learning shots and 4,096 decoding shots, and takes about 13 minutes on one GB200, most of it in the uniform arm. The measurements on this page use up to 2,097,152 learning shots and the stopping rule from the table above.

Step 1: Get the Circuit and Fit the TCBP Model

The circuit is downloaded from the bivariatebicyclecodes test data of the tesseract-decoder repository. The TCBP model is fitted once per code family and needs no information about the device.

import urllib.parse, urllib.request
import numpy as np, stim
import cudaq_qec as qec
from cudaq_qec.plugins import nv_qldpc
from cudaq_qec.plugins.nv_qldpc import tying

# si1000 memory circuit: [[144,12,12]] code, 12 rounds, Z basis, p = 0.004
name = ("r=12,d=12,p=0.004,noise=si1000,c=bivariate_bicycle_Z,nkd=[[144,12,12]],q=288,"
        "iscolored=True,A_poly=x^3+y+y^2,B_poly=y^3+x+x^2.stim")
url = ("https://raw.githubusercontent.com/quantumlib/tesseract-decoder/"
       "98c663db388ab095939647a165c87b4d31cdd6b1/testdata/bivariatebicyclecodes/"
       + urllib.parse.quote(name))
urllib.request.urlretrieve(url, "bb144_r12_si1000_p0.004.stim")

circuit = stim.Circuit.from_file("bb144_r12_si1000_p0.004.stim")
H, O, true_rates = tying.dem_arrays(tying.circuit_dem(circuit))   # true_rates: scoring only

tcbp_model = nv_qldpc.init_tcbp_model(H, seed=1)                  # about 10 s

Step 2: Learn the Rates From Detector Data

learn_noise takes the structure H, the recorded detector samples, and the TCBP model, and returns the learned rates together with a report.

dets = circuit.compile_detector_sampler(seed=10001).sample(2**16).astype(np.uint8)   # [N shots, 1728]
learned_rates, report = nv_qldpc.learn_noise(H, dets, tcbp_model, passes=16, tol=0)  # about 2 min
uniform_rate = report["start_rate"]                    # the uniform prior used below

passes is the maximum number of passes and tol is an early-stop threshold. Without them the defaults apply (passes=4, tol=0.1): learning runs at most 4 passes and stops earlier if a pass changes the rates by less than tol. tol=0 disables the early stop so that exactly passes passes run.

Step 3: Decode With Each Prior

Fresh detector shots are sampled together with their observable flips. The same shots are decoded three times, changing only error_rate_vec, and each prediction is compared with the sampled observables:

syndromes, observables = circuit.compile_detector_sampler(seed=778).sample(
    4096, separate_observables=True)
syndromes, observables = syndromes.astype(np.uint8), observables.astype(np.uint8)

tcbp = np.array(bytearray(tcbp_model), dtype=np.uint8)
bp = dict(use_sparsity=True, bp_method=0, max_iterations=10, clip_value=15.0,
          proc_float="fp32", use_osd=True, osd_method=4, osd_init_method="tcbp",
          tcbp_model=tcbp, bp_batch_size=4096)
priors = {"uniform": np.full(H.shape[1], uniform_rate),
          "learned": learned_rates,
          "oracle":  true_rates}

for name, rates in priors.items():
    decoder = qec.get_decoder("nv-qldpc-decoder", H,
                              error_rate_vec=np.clip(rates, 1e-9, 0.45), **bp)
    results = decoder.decode_batch(syndromes)
    errors = (np.asarray(results.result) > 0.5).astype(np.uint8)   # [shots, mechanisms]
    predicted = (errors @ O.T.astype(np.int32)) % 2                # predicted observable flips
    failures = int((predicted != observables).any(axis=1).sum())
    print(f"{name:8s} LER = {failures / len(observables):.3e} "
          f"({failures} failures in {len(observables)} shots)")

The decoders above are built without repeatable=True, so the counts can differ by a few failures from run to run (floating-point non-determinism).

Learning Time and Accuracy

Learning time is proportional to the number of shots and to the number of passes, and does not depend on p. On one GB200 the default settings need about 0.43 ms per shot; passes=16 needs about four times as long. The accuracy is the median over all 67,752 mechanisms of |log(learned rate / true rate)| (0 is perfect; for scale, the uniform prior scores 1.29, 1.23 and 1.18 at p = 0.002, 0.003, 0.004). Each accuracy cell reads “default / 16 passes (sampling floor)”.

Error of the Learned Rates Versus the Number of Shots

The plot shows the median |log(learned / true rate)| versus the number of learning shots, for p = 0.002, 0.003, 0.004. Solid lines are passes=16, tol=0, dotted lines are the default settings, and dashed lines with open squares are the sampling floor. Each point is a single sample.

  • With passes=16, tol=0 the error falls by about 1.4x for every doubling of the shots. At 2,097,152 shots it is 1.8x, 2.0x and 3.1x above the sampling floor for p = 0.002, 0.003, 0.004, and still falling.

  • With the default settings the error flattens: at 2,097,152 shots it stays 4.2x, 7.3x and 16x above the floor. Every pass uses all the shots, but the default runs at most 4 passes (passes=4), and every run here reached that limit; none was ended sooner by tol. Four passes are too few for the rates to converge, so with the default settings more shots give diminishing gains in accuracy.

  • Below about 66,000 shots the default gives the smaller error in the learned rates: with so little data, additional passes do not help (at 16,384 shots and p = 0.002 the error is 0.451 with 16 passes against 0.334 with the default). This is a statement about the rates only; the logical error rate at 65,536 and 131,072 shots is given in the next sections.

  • With passes=16, tol=0 the observed LER with the learned prior is within about 10% to 20% of the oracle LER already at 65,536 shots, and within about 10% at 131,072 shots.

  • The default settings are fine for a quick first estimate. At 65,536 shots and p >= 0.003 their LER is 1.3x to 1.5x that of the oracle, against about 1.1x with 16 passes.
